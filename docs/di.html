22Service Locator и DI-контейнер

Yii::$app как локатор сервисов, Yii::$container как контейнер внедрения зависимостей: регистрация, разрешение через конструктор и сеттеры, синглтоны, Instance::of(), практические сценарии.

⏱ ~5 мин 📚 2 главы руководства

Service Locator (Yii::$app, любой модуль) хранит именованные компоненты и отдаёт их по ID. DI-контейнер (Yii::$container) умеет создавать объекты, сам подставляя зависимости из типов конструктора. Локатор построен поверх контейнера: когда Yii::$app->db создаётся впервые, объект собирает контейнер.

Регистрируйте зависимости как можно раньше: приложение — в конфигурации (container), расширение — в своём bootstrap-классе. Внедрение через конструктор + интерфейсы даёт слабосвязанный и легко тестируемый код: в тестах подставляется заглушка.

Проверь себя5

Локатор отдаёт компоненты по строковому ID (Yii::$app->db); контейнер создаёт объекты по классу/интерфейсу, автоматически разрешая зависимости конструктора. Локатор использует контейнер для создания своих компонентов.

Когда объект не хранит изменяемого состояния и его дорого создавать — например, обёртка над файловым хранилищем или соединение.

Чтобы в параметрах конструктора сослаться на другую зарегистрированную зависимость по имени — контейнер подставит её при создании.

Ошибка создания: контейнер не знает, какой класс подставить. Нужно Yii::$container->set(Interface::class, Impl::class).

Yii::$container->set('yii\widgets\LinkPager', ['maxButtonCount' => 5]) или container.definitions в конфигурации.
