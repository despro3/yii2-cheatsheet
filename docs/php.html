Запуск и настройка

Каждый запрос начинается с чистого листа: PHP поднимается, компилирует файлы в опкоды, выполняет их и всё забывает. Кэш опкодов и настройки решают, сколько это стоит.

Главная особенность модели PHP — shared nothing: ни один запрос не видит память предыдущего. Глобальные переменные, статические свойства, открытые соединения — всё создаётся заново и уничтожается в конце. Отсюда простота отладки и отсюда же цена: код компилируется на каждом запросе, если его не закэшировать.

  1. PHP стартует в выбранном SAPI — php-fpm для веба, cli для консоли, встроенный сервер для разработки.
  2. Читается php.ini, подключаются расширения, применяются настройки пула.
  3. Входной файл разбирается и компилируется в опкоды — низкоуровневые инструкции Zend VM.
  4. OPcache кладёт опкоды в общую память: со второго запроса шаг компиляции пропускается.
  5. Опкоды выполняются; классы подтягиваются автозагрузчиком по мере первого обращения.
  6. Вывод уходит клиенту, память освобождается, всё состояние процесса сбрасывается.

советJIT нужен не всем

JIT компилирует горячие опкоды в машинный код и заметно ускоряет вычисления: обработку изображений, математику, разбор данных. Типичное веб-приложение упирается не в процессор, а в базу и сеть, поэтому там выигрыш от JIT обычно в пределах шума, а от OPcache — кратный.

Пространства имён и автозагрузка

Имя класса — это путь к файлу, по которому его найдут в момент первого обращения. Вся схема держится на одном соглашении и одной функции.

Пространство имён — это префикс к именам, не более: он не создаёт области видимости для переменных и не влияет на выполнение. Зато по полному имени класса автозагрузчик вычисляет путь к файлу — и подключает его ровно тогда, когда класс впервые понадобился.

граблиВнутри пространства имён \ обязателен для классов

В файле с namespace App; запись new DateTime() означает App\DateTime — и падает с «Class not found». Для функций правило мягче: если функции нет в текущем пространстве, PHP посмотрит в глобальном. Для классов такого запасного пути нет.

Ошибки и исключения

В PHP 8 почти всё, что раньше было предупреждением, стало исключением. Ловить их принято точечно, а не одним catch на весь файл.

Всё, что можно бросить, реализует Throwable. Дальше развилка: Error — это ошибки самого языка (не тот тип, деление на ноль, нет метода), Exception — ошибки приложения. Ловить Error обычно не нужно: он означает, что код написан неверно.

Предупреждения PHP — это не исключения

Обращение к несуществующему ключу, include пропавшего файла, деление на ноль через % — часть из этого по-прежнему диагностика движка, а не Throwable. Чтобы такие места тоже попадали в catch, их превращают в исключения обработчиком.

граблиcatch (Throwable) на каждом шаге прячет ошибки

Перехват всего подряд превращает TypeError и опечатку в имени метода в «ошибку сервиса»: приложение продолжает работать со сломанными данными. Ловите то, что умеете обработать, а общий catch оставьте одному месту — на границе, где формируется ответ.

Слева — классы и конструкции. Из встроенных классов исключений в приложении обычно бросают четыре-пять; остальные полезно узнавать в чужих трассировках.

Типы и приведение

Тип есть у значения, а не у переменной. Объявленный тип — это проверка на входе, и строгость этой проверки выбирает файл, из которого пришёл вызов.

В PHP тип принадлежит значению: переменная просто держит то, что в неё положили. Зато у параметров, свойств, возвращаемых значений и констант класса можно объявить тип — и тогда PHP проверяет значение на входе.

Что он сделает с неподходящим значением, решает не объявление, а файл, из которого сделан вызов: с declare(strict_types=1) в его первой строке несоответствие сразу даёт TypeError, без него PHP сначала попробует привести значение к нужному типу.

Операторы и выражения
Сравнение, выбор ветки и короткие записи «если пусто». Здесь же главное изменение PHP 8: число и нечисловая строка больше не равны.

Строки
Строка в PHP — это последовательность байтов, а не символов. Отсюда две половины стандартной библиотеки: байтовая и та, что с приставкой mb_.
Строка хранит байты. Пока текст в ASCII, байт и символ совпадают, и разницы не видно. Как только появляется кириллица или эмодзи, strlen() начинает считать не то, а substr() — резать символ пополам. Для текста берут функции mb_*, которые знают про кодировку.

Массив PHP — упорядоченная хэш-таблица. Порядок вставки сохраняется всегда, ключом может быть только int или string, всё остальное приводится: 1.7 станет 1, true — 1, null — пустой строкой, а строка "7" — числом 7.
Копирование и ссылки
Массив присваивается по значению, но копия делается лениво: пока никто не пишет, обе переменные смотрят в одни данные. Объект внутри массива при этом не копируется — копируется ссылка на него.
граблиЗабытый unset($row) после foreach по ссылке
После цикла $row остаётся ссылкой на последний элемент. Следующий foreach ($rows as $row) будет на каждом шаге писать в него — и массив закончится дублем предпоследнего значения. Либо unset() сразу после цикла, либо не брать по ссылке вовсе: array_map() или новый массив.

Fiber
Файберы
Кусок кода, который можно остановить на любой глубине вызовов и продолжить позже. Фундамент асинхронных библиотек, а не инструмент прикладного кода.
Файбер — это отдельный стек вызовов, которым управляют руками. Запустили, внутри дошли до Fiber::suspend() — выполнение вернулось туда, откуда запускали, вместе с переданным значением. Потом resume() — и файбер продолжил с той же строки.
Отличие от генератора одно, но решающее: генератор умеет останавливаться только в своём теле, а файбер — на любой глубине вложенных вызовов. Поэтому на файберах строят асинхронные библиотеки: код внутри выглядит обычным, синхронным, а ждёт он неблокирующе.
вниманиеФайбер — это не параллелизм
В один момент времени работает ровно один файбер: PHP по-прежнему однопоточен. Файберы переключаются только там, где кто-то явно вызвал suspend(), — это кооперативная многозадачность, а не потоки и не процессы.
граблиFiber::suspend() вне файбера — ошибка
Вызов снаружи бросает FiberError: Cannot suspend outside of a fiber. Поэтому библиотеки вроде Amp и ReactPHP прячут файберы внутри своего планировщика: прикладной код зовёт их await, а не Fiber::suspend() напрямую.

Файл, сетевое соединение, память и стандартный ввод — для PHP это один и тот же поток, который открывают одной функцией.
Всё, что читается и пишется, в PHP — поток. Путь при открытии может быть обычным файлом, адресом https://, псевдофайлом php://memory или чем-то, что зарегистрировала библиотека. Поэтому функции работы с файлами одинаково читают и локальный CSV, и тело HTTP-запроса.

вниманиеРефлексия дорога — кэшируйте результат

Как переезжать на новую версию
  1. Поднимите "php": "^8.4" в composer.json и выполните composer update — часть пакетов обновится сама.
  2. Прогоните тесты на новой версии с error_reporting(E_ALL) и включённым логированием: устаревшее проявится сразу.
  3. Соберите deprecated-сообщения из логов — это и есть список работ.
  4. Пропустите Rector с набором для целевой версии (withPhpSets) и просмотрите изменения глазами.
  5. Поднимите уровень PHPStan: на новой версии он видит больше.
  6. Выкатывайте на часть трафика, если есть такая возможность: часть несовместимостей вылезает только на реальных данных.

Строка "php": "^8.3" в require не даст установить проект туда, где стоит 8.1, и заставит Composer подбирать совместимые версии пакетов. А config.platform фиксирует версию, под которую собираются зависимости, даже если локально у вас новее.
вниманиеНовый синтаксис нельзя закрыть полифилом
Функцию можно дописать самому, а |>, хуки свойств и readonly — нет: файл с ними не разберётся на старой версии вовсе, даже если эта ветка кода никогда не выполняется. Поэтому в библиотеках, поддерживающих несколько версий, новый синтаксис появляется только со сменой мажорной версии пакета.
