:::lead
Приложение Yii — это объект `Yii::$app`, созданный входным скриптом по массиву-конфигурации. Он держит компоненты (БД, запрос, ответ, пользователь…), знает, где лежат контроллеры и представления, и проводит каждый запрос через свой жизненный цикл.
:::

## Что есть в приложении кроме MVC

:::cards
- **Входной скрипт** — единственный PHP-файл, доступный снаружи (`web/index.php` или консольный `yii`). Создаёт приложение и запускает обработку запроса.
- **Приложение** — глобальный объект, координирующий всё остальное; доступен как `Yii::$app`.
- **Компоненты приложения** — именованные сервисы (`db`, `request`, `user`, `cache`…), зарегистрированные в конфигурации и создаваемые лениво.
- **Модули** — самодостаточные мини-приложения со своими контроллерами, моделями и представлениями. См. [Модули](modules).
- **Фильтры** — код до и после действия контроллера: доступ, кеш, CORS. См. [Фильтры](filters).
- **Виджеты** — переиспользуемые блоки интерфейса внутри представлений. См. [Виджеты](widgets).
:::

## Входной скрипт {#vhodnoy-skript}

Он делает пять вещей: объявляет константы, подключает автозагрузчик Composer и класс `Yii`, читает конфигурацию, создаёт приложение и вызывает `run()`.

:::tabs
=== web/index.php
```php
<?php
defined('YII_DEBUG') or define('YII_DEBUG', true);
defined('YII_ENV') or define('YII_ENV', 'dev');

require __DIR__ . '/../vendor/autoload.php';          // автозагрузчик Composer
require __DIR__ . '/../vendor/yiisoft/yii2/Yii.php';  // класс Yii + автозагрузчик Yii + DI-контейнер

$config = require __DIR__ . '/../config/web.php';

(new yii\web\Application($config))->run();
```
=== yii (консоль)
```php
#!/usr/bin/env php
<?php
defined('YII_DEBUG') or define('YII_DEBUG', true);

require __DIR__ . '/vendor/autoload.php';
require __DIR__ . '/vendor/yiisoft/yii2/Yii.php';

$config = require __DIR__ . '/config/console.php';

$exitCode = (new yii\console\Application($config))->run();
exit($exitCode);
```
:::

Константы объявляют в самом начале, до подключения других файлов:

:::kv
`YII_DEBUG` — отладочный режим: подробные ошибки со стеком, больше логов. По умолчанию `false`
`YII_ENV` — окружение: `prod` (по умолчанию), `dev`, `test`; порождает `YII_ENV_PROD`, `YII_ENV_DEV`, `YII_ENV_TEST`
`YII_ENABLE_ERROR_HANDLER` — включать ли обработчик ошибок Yii. По умолчанию `true`
:::

`defined('X') or define('X', v)` — идиома «определить, если ещё не определено»: так константу можно переопределить снаружи, например в тестовом входном скрипте.

## Объект приложения

Два вида: `yii\web\Application` для HTTP и `yii\console\Application` для команд. Оба наследуют `yii\base\Application`, которая в свою очередь — [модуль](modules) и [Service Locator](di).

### Обязательные свойства

```php title="config/web.php"
return [
    'id' => 'basic',                    // уникальный идентификатор приложения
    'basePath' => dirname(__DIR__),     // корень с кодом; задаёт псевдоним @app
    // ...
];
```

### Свойства, которые настраивают чаще всего

:::kv
`aliases` — массив псевдонимов путей: `['@uploads' => '@webroot/uploads']`. Удобнее, чем `Yii::setAlias()` в коде
`bootstrap` — что создать при старте каждого запроса: ID компонентов/модулей, классы, конфиги, замыкания. Компонент с `BootstrapInterface` получит вызов `bootstrap($app)`. Держите список коротким — он выполняется всегда
`components` — главное свойство: регистрация компонентов приложения (см. ниже)
`controllerMap` — явное соответствие ID контроллера → класс, когда соглашение об именах не подходит
`controllerNamespace` — пространство имён контроллеров, по умолчанию `app\controllers`; `admin/post` ищется в `app\controllers\admin\PostController`
`modules` — подключённые модули: `'forum' => ['class' => 'app\modules\forum\Module']`
`params` — глобальные параметры: `Yii::$app->params['adminEmail']`. Обычно подключают `config/params.php`
`language` / `sourceLanguage` — язык интерфейса (`ru-RU`) и язык исходного кода (`en-US` по умолчанию); см. [i18n](i18n)
`timeZone` — часовой пояс приложения, по сути `date_default_timezone_set()`
`catchAll` — только web: маршрут, обрабатывающий все запросы (режим обслуживания): `['site/offline', 'param' => 'value']`
`name`, `version`, `charset` — название для показа пользователям, версия, кодировка (`UTF-8`)
:::

### Свойства с разумными умолчаниями

:::kv
`defaultRoute` — маршрут без явного указания: `site` для web (→ `site/index`), `help` для консоли
`layout`, `layoutPath`, `viewPath` — шаблон по умолчанию `main` в `@app/views/layouts`, представления в `@app/views`. `layout => false` отключает шаблон
`runtimePath` — временные файлы (логи, кеш): `@app/runtime`, псевдоним `@runtime`. Должна быть доступна на запись и закрыта от веба
`vendorPath` — пакеты Composer: `@app/vendor`, псевдоним `@vendor`
`extensions` — список установленных расширений; Composer сам генерирует `@vendor/yiisoft/extensions.php`
`enableCoreCommands` — консоль: включать ли встроенные команды (`migrate`, `cache`, `asset`…). По умолчанию `true`
:::

## События приложения

Обработчики вешают прямо в конфигурации через синтаксис `'on имяСобытия'` или кодом после создания приложения:

```php
return [
    'on beforeRequest' => function ($event) {
        // приложение создано, запрос ещё не обрабатывался — удобно выбрать язык по домену
    },
    'on beforeAction' => function (\yii\base\ActionEvent $event) {
        if ($somethingWrong) {
            $event->isValid = false;   // отменить выполнение действия
        }
    },
    'on afterAction' => function (\yii\base\ActionEvent $event) {
        $event->result = strtoupper($event->result);   // изменить результат действия
    },
];
```

| Событие | Когда | Полезно для |
|---|---|---|
| `beforeRequest` | до начала обработки запроса | переключение языка, темы, редиректы на обслуживание |
| `afterRequest` | после обработки, до отправки ответа | постобработка, статистика |
| `beforeAction` | перед действием; сначала у приложения, затем у модуля, затем у контроллера | проверки доступа «на самом верху» |
| `afterAction` | после действия; в обратном порядке: контроллер → модуль → приложение | обёртка результата |

> [!NOTE]
> Если один из обработчиков `beforeAction` установил `isValid = false`, остальные `beforeAction` уже не вызываются и действие не выполняется.

## Жизненный цикл приложения

:::steps
1. **Входной скрипт читает конфигурацию** — обычный PHP-массив из `config/web.php`.
2. **Создаётся объект приложения**: `preInit()` применяет критичные свойства (`basePath`), регистрируется обработчик ошибок, применяется остальная конфигурация, `init()` вызывает `bootstrap()` — подключаются расширения и компоненты из `bootstrap`.
3. **`run()` обрабатывает запрос**: событие `beforeRequest` → разбор маршрута компонентом `request` → создание модуля/контроллера/действия → выполнение → событие `afterRequest` → отправка ответа.
4. **Скрипт получает код выхода** и завершает работу.
:::

Подробнее о каждом шаге — в разделе [Жизненный цикл запроса](lifecycle).

## Компоненты приложения

Приложение — это [Service Locator](di): набор именованных объектов, к которым обращаются как `Yii::$app->id`. Компонент создаётся при первом обращении и дальше переиспользуется в рамках запроса.

```php title="config/web.php"
'components' => [
    'cache' => 'yii\caching\ApcCache',                 // просто имя класса
    'db' => [                                          // массив конфигурации
        'class' => 'yii\db\Connection',
        'dsn' => 'mysql:host=localhost;dbname=demo',
        'username' => 'root',
        'password' => '',
        'charset' => 'utf8',
    ],
    'search' => function () {                           // фабрика-замыкание
        return new app\components\SolrService('127.0.0.1');
    },
],
```

> [!TIP]
> Компоненты — по сути глобальные переменные. Регистрируйте то, что действительно нужно всему приложению; остальное создавайте локально или получайте через [DI-контейнер](di) — код будет проще тестировать.

Если компонент нужен в каждом запросе, даже когда к нему явно не обращаются (например, `log` должен ловить сообщения с самого начала), добавьте его ID в `bootstrap`:

```php
'bootstrap' => ['log'],
```

### Встроенные компоненты

У них фиксированные ID и классы по умолчанию — достаточно указать только нужные свойства.

| ID | Класс | За что отвечает |
|---|---|---|
| `request` | `yii\web\Request` | параметры запроса, заголовки, куки, разбор маршрута |
| `response` | `yii\web\Response` | код состояния, заголовки, тело, форматирование ответа |
| `urlManager` | `yii\web\UrlManager` | разбор и генерация URL, правила ЧПУ |
| `user` | `yii\web\User` | текущий аутентифицированный пользователь (только web) |
| `session` | `yii\web\Session` | сессия и flash-сообщения (только web) |
| `db` | `yii\db\Connection` | соединение с БД; класс и `dsn` нужно указать явно |
| `errorHandler` | `yii\web\ErrorHandler` | перехват ошибок и исключений |
| `log` | `yii\log\Dispatcher` | маршрутизация сообщений лога по целям |
| `view` | `yii\web\View` | рендеринг представлений, регистрация скриптов |
| `assetManager` | `yii\web\AssetManager` | публикация и подключение JS/CSS |
| `formatter` | `yii\i18n\Formatter` | форматирование дат, чисел, размеров |
| `i18n` | `yii\i18n\I18N` | переводы сообщений |
| `mailer` | `yii\symfonymailer\Mailer` / `yii\swiftmailer\Mailer` | отправка писем |
| `cache` | по соглашению `yii\caching\Cache` | кеш данных; не встроен, но ожидается многими компонентами |

:::quiz Проверь себя
Q: Какие два свойства приложения обязательны в конфигурации?
A: `id` и `basePath`. Второе определяет псевдоним `@app`, от которого считаются `runtimePath`, `viewPath` и другие пути.
Q: Когда создаётся компонент приложения, объявленный в `components`?
A: Лениво — при первом обращении `Yii::$app->id`. Чтобы создать его при старте каждого запроса, ID добавляют в `bootstrap`.
Q: В каком порядке срабатывают события `beforeAction` и `afterAction`?
A: `beforeAction`: приложение → модуль → контроллер. `afterAction`: контроллер → модуль → приложение.
Q: Как перевести сайт в режим обслуживания одной строкой конфигурации?
A: `'catchAll' => ['site/offline']` — все запросы пойдут в это действие.
Q: Зачем идиома `defined('YII_DEBUG') or define('YII_DEBUG', true)` вместо простого `define`?
A: Чтобы константу можно было определить раньше (например, в тестовом входном скрипте или на сервере) без правки кода — повторный `define` вызвал бы ошибку.
:::
